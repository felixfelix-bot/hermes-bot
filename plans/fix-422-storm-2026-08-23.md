# Plan: Fix 422 Request Storm + Early Bail for Malformed Bodies

**Date:** 2026-08-23
**Status:** EXECUTING

## Root Cause (captured via 422 body logging)

The 422 errors were caused by **model-only requests** (body has `['model']` but no `messages` field) hitting the full external failover chain. Every provider rejects them with 422 "Field required at 'messages'". These were likely health-check or model-availability probes from the gateway, sent every ~13 seconds, each wasting 2-5 seconds cycling through oxalpha → neuralwatt → deepinfra before returning 422.

The 422 body capture confirmed:
- neuralwatt: `{"error":{"message":"Field required at 'messages'","type":"invalid_request_error"}}`
- deepinfra: `{"error":{"message":"Field required","type":"invalid_request_error","param":"messages","code":"missing_required_parameter"}}`

This is NOT a field-stripping issue — the `messages` field was never in the body.

## Changes

### D1: Add `messages` presence check before external failover
In `_try_external_failover`, return False immediately if the body has no `messages` field, instead of cycling through every provider.

### D2: Remove the temporary debug logs
Remove the `neuralwatt body keys:` debug line (its purpose is served — we captured the 422 body and found the root cause). Keep the 422 body capture logging (it's useful for future diagnosis).

### D3: Also guard the `_try_opencode_go` and non-z.ai model routing paths
These also forward to external providers and should reject model-only bodies early.
